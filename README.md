# НарядAI · McLOVINs

Проект для кейса №1 АО «Костанайские минералы» на QOSTANAI AI INDUSTRY HACKATHON 2026.
Мастер выдаёт наряд с телефона, исполнитель выполняет работу, система контролирует сроки,
а ИИ помогает проверить результат. Финальное решение остаётся за мастером.

**Текущее состояние: этап 4 — русская PWA исполнителя и панель мастера.**
Работают API, четыре роли, доступ по участкам, PostgreSQL и воспроизводимые демоданные.
Выдача и выполнение наряда проверены через настоящий HTTP-сервер; изменения защищены
версиями, идемпотентностью и аудитом. Добавлены канбан, мобильная сдача с фото/материалами,
сохранённые снимки и офлайн-очередь с явным разрешением конфликтов.
Уведомления, worker, реальный ИИ и аналитика ещё не реализованы.

## Быстрый запуск

Основная среда — Ubuntu/WSL, Python 3.13.13 и uv.
Все команды ниже выполняются **в терминале Ubuntu**, из корня проекта:

```bash
cd /home/zlhrs/Industry_Hackathon
uv sync --locked
uv run --locked python scripts/dev_database.py bootstrap
uv run --locked python scripts/dev_database.py start
uv run --locked alembic upgrade head
uv run --locked uvicorn naryadai.app:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log --no-proxy-headers
```

`bootstrap` нужен один раз: скачивает пакет PostgreSQL 16 из настроенного Ubuntu apt
и распаковывает в игнорируемый `var/postgres/runtime`, без sudo и изменения системного сервиса.
Требуются apt-get, dpkg-deb и совместимые системные библиотеки Ubuntu; проверено на текущем WSL.
`start` создаёт отдельный кластер на **127.0.0.1:55432**, базы `naryadai` и `naryadai_test`,
случайные пароли и локальный `.env`, если его ещё нет. Приложение использует отдельную
роль без superuser/создания БД. Существующий `.env` не перезаписывается.
Статус и остановка: `uv run python scripts/dev_database.py status` / `stop`.
В подготовленной рабочей папке кластер и демоданные уже созданы; повторять bootstrap не нужно.
При обновлении с этапа 2 выполните `uv sync --locked` и `uv run --locked alembic upgrade head`: миграция
`0002_order_workflow` сохраняет существующие записи. Повторный seed для обновления не нужен.

uv создаёт `.venv` и использует версии из `uv.lock`; ручная активация не нужна.
Не используйте Windows Python для WSL-окружения.

- [Проверка процесса](http://localhost:8000/api/v1/health/live).
- [Готовность БД и версии схемы](http://localhost:8000/api/v1/health/ready).
- [Swagger API](http://localhost:8000/docs). Остановка API: Ctrl+C.

Readiness возвращает 503 без доступной БД или с неподходящей миграцией.
API не применяет миграции при старте. `--no-access-log` исключает полные URL из журнала Uvicorn;
приложение пишет шаблоны маршрутов без query/body/секретов.
`--no-proxy-headers` сохраняет адрес реального TCP-клиента для лимита входа.
При развёртывании за reverse proxy доверенные прокси настраиваются явно.

## Интерфейс

После запуска API откройте второй терминал Ubuntu в корне проекта:

```bash
uv run --locked python scripts/dev_frontend.py bootstrap
bash scripts/frontend.sh ci
bash scripts/frontend.sh run dev -- --host 127.0.0.1 --port 5173
```

[Открыть НарядAI](http://localhost:5173). Вход — существующие демо-логины и локальный секрет ниже.
Node 24.21.0 устанавливается внутри игнорируемого `var/node`, официальный архив проверяется
по SHA-256; системный Node не меняется. При своём Node соблюдайте `.node-version`.

Мастер получает канбан, фильтры, выдачу и управление нарядами; исполнитель — свою очередь,
действия и сдачу ремонта; руководитель — просмотр; администратор — просмотр справочников.
Редактор справочников доступен через admin API; его UI — последующее расширение.

Для service worker и проверки без сети нужна production-сборка:

```bash
bash scripts/frontend.sh run build
bash scripts/frontend.sh run preview -- --host 127.0.0.1 --port 5173
```

Dev и preview не запускаются одновременно на одном порту. Оба проксируют `/api` к API на 8000;
серверная переменная `NARYADAI_API_TARGET` позволяет выбрать другой адрес.
Действия исполнителя сохраняются до отправки; неподтверждённый статус не выдаётся за серверный.
Фото требуют связи. Выход очищает локальные снимки и очередь сотрудника.
Подробности офлайн-контракта, изолированные браузерные тесты и ограничения — [этап 4](docs/stage-04.md).
Preview — локальная проверка; HTTPS, установка на реальные Android/iOS и замеры мобильной сети — этап 8.

## Демоданные и вход

В текущей рабочей папке общий **локальный** секрет demo-учёток записан в
`var/demo-credentials.txt` (игнорируется Git, права 600). Не добавляйте файл в репозиторий.
Логины: `demo.master1`, `demo.master2`, `demo.executor01` … `demo.executor15`,
`demo.manager`, `demo.admin`.

Для новой пустой БД сначала примените миграцию, затем задайте собственный секрет
(6–128 символов; ввод скрыт, значение не сохраняется в истории команд):

```bash
read -rs -p "Demo secret: " NARYADAI_DEMO_SECRET
export NARYADAI_DEMO_SECRET
uv run --locked python -m naryadai.demo --anchor 2026-10-05 --seed 42
unset NARYADAI_DEMO_SECRET
```

Seed создаёт 4 участка, 25 машин, 19 сотрудников, 3 бригады, 20 шифров,
40 материалов, 100 нормативов и 600 нарядов за несколько месяцев.
Есть четыре синтетические закономерности для будущей аналитики.
Повтор с теми же параметрами не дублирует записи и не меняет пароль;
другие параметры в непустой БД и production запрещены. Данные не удаляются.
Фото отсутствуют; исторические оценки обозначены как синтетические fixtures,
а не результат работы подключённого ИИ.

В Swagger выполните `POST /api/v1/auth/login` с JSON
`{"login":"demo.master1","secret":"ваш локальный секрет"}`.
Полученный `access_token` вставьте в **Authorize**.
Доступные операции:

- `GET /api/v1/auth/me`, `POST /api/v1/auth/logout`.
- `GET /api/v1/catalog`, `GET /api/v1/catalog/equipment/{id}`.
- Мастер/руководитель/админ: список сотрудников доступных участков.
- Админ: создание/изменение справочников, создание учёток, смена роли/секрета/участков.

Сессии по умолчанию действуют 8 часов; в БД сохраняются только отпечатки токенов.
PIN/пароль хешируется Argon2id. Лимиты входа хранятся в PostgreSQL:
5 попыток на логин и 50 на адрес за 15 минут, включая успешные входы.
Смена доступа отзывает все сессии сотрудника. Не используйте общий demo-секрет для пилота.

## Наряды и фотографии

Все маршруты ниже имеют префикс `/api/v1` и требуют Bearer-токен.

| Маршрут | Возможность |
| --- | --- |
| `POST /work-orders` | Мастер выдаёт наряд; номер и время создаёт сервер |
| `GET /work-orders` | Фильтры, счётчики статусов, пагинация |
| `GET /work-orders/{id}` | Карточка, материалы по сдачам, фото, история оценок |
| `POST /work-orders/{id}/actions` | Принять, очередь, отказ, старт/пауза, сдача; действия мастера |
| `GET /work-orders/{id}/events` | Аудит с курсором `after_sequence` |
| `GET /equipment/{id}/history` | История оборудования для мастера/руководителя |
| `GET /workload` | Свободен, занят, очередь, не на смене |
| `POST /work-orders/{id}/photos` | Загрузить фото до/после |
| `GET /work-orders/{id}/photos/{photo_id}` | Получить приватный JPEG |

Мастер изменяет только выданные им наряды. Исполнитель видит только свои назначения;
руководитель читает данные доступных участков. Администратор управляет справочниками
и доступом, включая `is_on_shift`, но не получает полномочия мастера.
Снять со смены исполнителя с активной работой нельзя.

Создание, действия и фото требуют `Idempotency-Key`: 8–128 ASCII-символов
из `A–Z`, `a–z`, `0–9`, `.`, `_`, `:`, `-`. Новое намерение — новый ключ.
При сетевом повторе отправляются прежний ключ и **тот же payload**.
Действия и фото также требуют `expected_version` из последнего ответа/карточки.
Ошибка `409 version_conflict` означает: перечитать карточку и заново согласовать действие.
Повтор успешного запроса возвращает сохранённый ответ, который может быть старее текущей карточки.
Подробные контракты, примеры и ограничения — в [отчёте этапа 3](docs/stage-03.md).

Фотография передаётся как сырые байты тела с `Content-Type: image/jpeg`, `image/png`
или `image/webp`; параметры `kind=before|after` и `expected_version` находятся в query.
До 5 фото до ремонта; до 5 фото после на каждую попытку выполнения.
По умолчанию вход ограничен 10 MiB и 24 млн пикселей, результат — JPEG до 2048 px
по большей стороне и 2 MiB. EXIF/геометки удаляются. HEIC и анимации не принимаются.
Файлы хранятся в `var/photos`, не публикуются статическим сервером и не попадают в Git.

Сдача создаёт состояние `completed`: оно ожидает проверки. Реальный ИИ/worker появятся
на следующих этапах; отсутствие фото не приводит к автоматическому успешному закрытию.

## Проверки

```bash
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
uv run --locked pytest --require-db --cov=naryadai --cov-report=term-missing
uv run --locked alembic check
uv build
bash scripts/frontend.sh run lint
bash scripts/frontend.sh run typecheck
bash scripts/frontend.sh run format:check
bash scripts/frontend.sh test
bash scripts/frontend.sh run build
git diff --check
```

Интеграционные тесты требуют настоящую PostgreSQL: локальный helper сохраняет URL в
`var/postgres/test-url`; для другой среды задайте `NARYADAI_TEST_DATABASE_URL`.
Имя тестовой БД должно оканчиваться на `_test`.
Каждый тест создаёт/удаляет только свою случайную схему.
Без БД обычный pytest явно пропускает интеграционные тесты; `--require-db` запрещает такой пропуск.
CI использует отдельную PostgreSQL service database и тот же обязательный флаг.
Предупреждения считаются ошибками, порог покрытия ветвей — 90%; это не процент готовности кейса.
GitHub Actions подготовлен, удалённый запуск пока не подтверждён.

## Другой PostgreSQL / Docker

Можно использовать свою PostgreSQL 16, указав в локальном `.env`
`NARYADAI_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:PORT/DATABASE`.
Пароль со специальными символами должен быть URL-encoded.
Полный набор параметров — в `.env.example`; настройки проверяются при запуске.

`compose.yaml` содержит альтернативный локальный PostgreSQL 16.15.
Задайте `NARYADAI_POSTGRES_PASSWORD`, выполните `docker compose up -d postgres`
и настройте URL вручную. Compose и helper используют один порт: одновременно не запускаются.
Compose не запускает приложение, миграции или seed; его стандартный пользователь —
владелец локального кластера. Для пилота выделите отдельную роль приложения.
Docker недоступен в текущем WSL, поэтому этот альтернативный запуск не проверен.
