# Телефон через Cloudflare Tunnel

Команды выполняются в **Ubuntu/WSL**, из корня проекта. Телефон может быть в другой
Wi-Fi-сети или пользоваться мобильным интернетом: открывать порты Windows/роутера не нужно.

## Запуск в подготовленном проекте

```bash
cd /home/zlhrs/Industry_Hackathon
uv run --locked python scripts/dev_database.py start
uv run --locked python scripts/phone_tunnel.py
```

Дождитесь строки **Open on your phone: https://…trycloudflare.com**. Откройте именно этот
адрес на телефоне. Старый адрес от отдельно запущенного `cloudflared` больше не нужен:
его можно остановить Ctrl+C в его терминале. `localhost` на телефоне — сам телефон.

Скрипт собирает PWA, запускает отдельный API на 127.0.0.1:8001, preview на 127.0.0.1:5174,
worker и HTTPS-туннель. Существующие процессы на 8000/5173 он не останавливает.
Если worker уже запущен в другом терминале, используйте:

```bash
uv run --locked python scripts/phone_tunnel.py --no-worker
```

Занятые порты не перехватываются и не заменяются автоматически. При необходимости:

```bash
uv run --locked python scripts/phone_tunnel.py --api-port 8002 --web-port 5175
```

Оставьте терминал открытым и ноутбук включённым, без спящего режима. **Ctrl+C** завершает
только процессы этого запуска; PostgreSQL и существующие локальные процессы остаются.
Настройки `.env`, ключи, фотографии и записи в базе не перезаписываются. Скрипт не запускает
seed или миграции. Действия с телефона меняют ту же базу, что и интерфейс на ноутбуке.

Вход: `master.sadykov` (мастер), `exec.amanov` (исполнитель), `manager.tulegen`
(руководитель). Пароль — в локальном `var/industrial-credentials.txt`; не публикуйте этот файл.

## Первый запуск на другом ноутбуке

Нужны подготовленная база с пользователями, `.env` и зависимости:

```bash
uv sync --locked
uv run --locked python scripts/dev_frontend.py bootstrap
bash scripts/frontend.sh ci
uv run --locked alembic upgrade head
cloudflared --version
```

Если cloudflared отсутствует, установите его **в Ubuntu**, следуя
[официальной инструкции Cloudflare](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/).
В текущем WSL cloudflared уже установлен. Для подготовки PostgreSQL смотрите корневой README.
Скрипт не устанавливает системные программы автоматически.

## Что проверить на телефоне

1. Откройте ссылку в Chrome на Android или Safari на iPhone. Войдите.
2. Установите приложение: меню браузера → «Установить приложение» / «На экран Домой».
3. На ноутбуке войдите мастером, на телефоне исполнителем. Выдайте исполнителю наряд:
   список и уведомления должны обновиться без ручного обновления страницы.
4. Откройте наряд, примите его, начните работу. При сдаче проверьте выбор/съёмку фото;
   разрешите камеру, если браузер спрашивает. Фото загружаются при наличии связи.
5. При доступной настройке включите push-уведомления в приложении. На iPhone проверяйте
   установленную PWA; разрешение уведомлений даётся отдельно. Доставка требует серверной
   VAPID-настройки из `.env` и работающего worker; сам туннель её не заменяет.
6. После загрузки списка отключите сеть: проверьте сохранённые данные и очередь действий.
   Верните сеть и убедитесь, что очередь отправилась либо показала понятный конфликт.
7. Войдите руководителем: откройте аналитику и скачайте Excel-отчёт.

Проверка в настольном браузере не заменяет этот прогон на физических Android/iPhone.

## Обновление push на установленном приложении

После обновления сборки откройте текущую HTTPS-ссылку в Chrome, обновите страницу и
оставьте её открытой несколько секунд для установки нового service worker. Затем
снова откройте установленную PWA и проверьте новое уведомление. Существующие подписки
и данные не нужно удалять. Для проверки перехода сверните приложение, выдайте новый
наряд его исполнителю и нажмите на системное уведомление: ожидается открытие приложения
и карточки (либо вход, если сессия истекла). Старые уведомления могут сохранять прежнюю иконку.

Исправление обработчика: сначала фокус существующего окна, затем переход; если окно
недоступно, открывается новое. PNG-иконка и монохромный badge заданы явно.
Браузерные тесты проверяют обработчик, ресурсы и Notification; нажатие на настоящем
Android/Chrome после этого исправления требует отдельного прогона на телефоне.

## Если что-то не открылось

- **Blocked request / host is not allowed:** используйте адрес, напечатанный именно
  `phone_tunnel.py`. Он автоматически разрешает конкретный новый hostname в Vite и API.
  Не добавляйте `allowedHosts: true` или общий `.trycloudflare.com`.
- **Cloudflare did not connect:** смотрите `cloudflared.log` в указанной скриптом папке;
  проверьте интернет/VPN/доступность сервиса. Quick Tunnels несовместимы с некоторыми
  настройками `~/.cloudflared/config.yaml`; существующую конфигурацию скрипт не изменяет.
- **Readiness failed:** проверьте, что база запущена и `alembic upgrade head` выполнен.
- **502/ошибка подключения:** дождитесь строки Open on your phone, проверьте терминал,
  интернет ноутбука и отсутствие спящего режима.
- **Port … is busy:** остановите предыдущий мобильный запуск или задайте другие порты.
- **429 при входе:** подождите 15 минут: лимиты входа сохранены. За туннелем API видит
  локальный адрес прокси; общий лимит — 50 попыток за 15 минут, включая успешные входы.
- **Старое установленное приложение не открывается:** при новом запуске Quick Tunnel
  адрес меняется. Откройте новую ссылку и переустановите PWA. Сессии, офлайн-очередь и push
  привязаны к адресу сайта: синхронизируйте несохранённые действия до остановки туннеля.

Приватные логи запуска находятся в `var/phone-tunnel/<идентификатор>/`; актуальная для
этого запуска ссылка — в `url.txt` рядом с логами. Папка исключена из Git.

## Как устроено

Телефон → HTTPS Cloudflare → локальный preview → `/api` и WebSocket → локальный API.
Одна внешняя ссылка обеспечивает HTTPS для PWA и WSS для обновлений. Скрипт разрешает
только свой точный hostname и HTTPS-origin; Host и Origin сохраняются при проксировании,
а backend проверяет их самостоятельно. API работает без Swagger и доверия произвольным
forwarded-заголовкам. Секреты остаются на сервере.

Это временный доступ для проверки и показа, а не промышленное развёртывание.
[Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)
выдаёт временный адрес и не гарантирует доступность. Для устойчивой установленной PWA
нужны постоянный домен и named tunnel/развёрнутый сервер.
[Vite рекомендует точный список разрешённых хостов](https://vite.dev/config/server-options#server-allowedhosts).
