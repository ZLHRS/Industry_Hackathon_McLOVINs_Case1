# Импорт оборудования и материалов из Excel

Импорт помогает начать работу с существующими справочниками предприятия.
Доступен **администратору** в разделах **«Справочники → Оборудование»** и
**«Справочники → Материалы»**, кнопка **«Импорт Excel»**.

## Как загрузить данные

1. Скачайте шаблон в окне импорта.
2. Заполните лист оборудования, материалов или оба. Не меняйте заголовки.
   Коды действующих участков указаны на отдельном справочном листе шаблона.
3. Выберите файл `.xlsx` и нажмите **«Проверить файл»**.
4. Посмотрите новые и уже существующие записи, исправьте отмеченные ошибки.
5. Подтвердите добавление. До этого момента справочники не изменяются.

| Оборудование | Материалы |
| --- | --- |
| Код существующего активного участка | Код материала |
| Инвентарный номер | Название |
| Название | Единица измерения |
| Тип оборудования | |
| Критичность от 1 до 5 | |

Для типа оборудования используйте принятые на предприятии значения: по этому полю
система связывает оборудование с нормативами. Коды и инвентарные номера храните
как текст, особенно если они начинаются с нулей.

## Что происходит с существующими данными

- Полное совпадение записи пропускается — дубликат не создаётся.
- Тот же код или инвентарный номер с другими значениями считается конфликтом.
  Исправьте файл либо измените существующую запись через обычную форму справочника.
- Дубли внутри файла и неизвестный участок показываются с номером строки.
- Если есть ошибки, **весь импорт блокируется**. Частичного сохранения нет.
- Если данные изменились между проверкой и подтверждением, нужна повторная проверка.
- Повторная отправка не создаёт дубликаты. Если ответ потерялся, проверьте файл снова:
  уже сохранённые позиции будут отмечены как существующие.

Закрытие окна до подтверждения ничего не сохраняет. Загрузка сотрудников, паролей
и истории нарядов в этот этап не входит. Импорт не перезаписывает и не удаляет записи.

## Формат и ограничения

До **500 записей суммарно** на двух листах и **2 МиБ** на файл. Старый `.xls`, книги
с макросами, формулами или внешними ссылками не поддерживаются. Скопируйте нужные
значения в скачанный шаблон. Данные размещайте в первых 500 строках после заголовка
без больших пустых промежутков. Пустые строки не являются записями, но номер строки
и число столбцов тоже ограничены, чтобы случайно испорченная книга не перегружала сервер.

Сервер проверяет структуру и размер распакованного файла, затем повторяет проверку
перед сохранением. Обработка выполняется с ограничением параллелизма. Для разбора
используются `openpyxl` и `defusedxml`, рекомендованный в
[документации openpyxl по безопасности](https://openpyxl.readthedocs.io/en/stable/index.html#security).

## Проверка функции

Серверные проверки покрывают права, ошибки файла, конфликты, повторную отправку
и сохранение одной транзакцией. Браузерные сценарии — шаблон, предварительный
просмотр, отмену, подтверждение и узкий экран.

Для браузерных проверок после запуска изолированного стенда выполните:

```bash
uv run --locked python scripts/frontend_import_fixtures.py
```

Файлы создаются только в игнорируемой папке `tmp/excel-import-fixtures`.
Затем запускайте `frontend/e2e/catalog-import.spec.ts` тем же способом,
что остальные браузерные тесты проекта. Рабочая база для проверки не используется.

Это дополнительная возможность для внедрения: она сокращает ручное заполнение
справочников. Фактическое время переноса и пользу для предприятия нужно измерять
на его данных; конкурсные баллы автоматически за наличие импорта не начисляются.
