закрытие. Оценка мастера и обоснование записались в аудит, исходная оценка ИИ сохранилась.

- Полный backend-прогон: **307 тестов**, покрытие с учётом ветвлений **91,09%**.
- После ужесточения критериев добавлены три регрессии; отдельно пройдены все
  **8 тестов оценочного скрипта**, включая эти три. Полный прогон после них не повторялся.
- Ruff, форматирование 91 Python-файла и строгий mypy 40 исходных файлов — пройдены.
- Сценарий без сети не обращается к API; проверены отсутствие ключа и остановка при квоте.
- На основном preview проверены вход, карточка, уведомления, push-конфигурация

## Как повторить

Из терминала Ubuntu в корне проекта:

```bash
# Подготовить примеры и изображения без ключа и без сетевых запросов.
uv run --locked python scripts/eval_ai.py

# Один платный запрос с синтетическим текстом для проверки подключения.
uv run --locked python scripts/check_ai.py

# До восьми последовательных платных запросов с синтетическими данными.
uv run --locked python scripts/eval_ai.py --live
```

Каждый запуск оценочного скрипта сохраняет отдельную папку в `tmp/ai-eval`.
Скрипт не читает основную БД и пользовательские фотографии. Обычные тесты проекта
используют тестовый транспорт и платный API не вызывают.

Для проверки через интерфейс создайте и сдайте новый наряд: сохранённый fallback
после смены ключа не переписывается автоматически. Настройка анализа разрешённых
фотографий и пользовательский сценарий описаны в [этапе 6](stage-06.md).

Остаётся собрать разрешённые реальные фотографии оборудования до/после с экспертной
оценкой, проверить ошибки и отказы модели на этом наборе. Проверки физических
Android/iOS, внешней push-доставки и HTTPS относятся к этапу развёртывания.
