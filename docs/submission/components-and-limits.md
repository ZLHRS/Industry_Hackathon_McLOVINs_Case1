# Компоненты, данные и границы прототипа

Команда McLOVINs, ТехНаряд, кейс №1. Источник требований — два предоставленных PDF.
Ниже раскрытие компонентов по положению §5.8/§6.4, а не заявление о сертификации.

| Область | Использовано | Роль |
| --- | --- | --- |
| Сервер | Python, FastAPI, Pydantic | HTTP API, проверка входных данных и прав |
| Хранение | PostgreSQL, SQLAlchemy, Alembic | Транзакции, история, миграции |
| Интерфейс | React, TypeScript, Vite | Русская адаптивная PWA |
| Работа без сети | Service Worker, IndexedDB | Оболочка приложения и очередь разрешённых действий |
| Уведомления | WebSocket, Web Push/VAPID | Обновления, напоминания и push |
| Проверка ремонта | Собственные правила и OpenAI Responses API при настройке | Смысловая/визуальная оценка с решением мастера |
| Отчёты и фото | XlsxWriter, Pillow | Excel, обработка изображений |
| Развёртывание | Docker Compose, Caddy, Cloudflare Tunnel | HTTPS-доступ к локальному компьютеру |
| Проверки | pytest, Ruff, mypy, Vitest, ESLint, Playwright | Серверная, статическая и браузерная верификация |
| Разработка | OpenAI Codex и агенты | Анализ требований, реализация, ревью и подготовка материалов |

Точные версии: `uv.lock`, `frontend/package-lock.json`; исходники и инструкции в
репозитории. Лицензии внешних зависимостей сохраняются у их правообладателей.
Использование стороннего компонента не означает авторство команды на этот компонент.

## Собственная логика решения

Граф наряда и роли; транзакционная история, версии и повторная доставка; адресация
сроков и эскалаций; правила проверки ремонта и безопасная обработка ответа модели;
рейтинги, учёт простоя, статистические сигналы; интерфейс рабочих сценариев и seed.
Команда должна проверить и уметь объяснить эти части независимо от помощи Codex.

## Данные

Демонстрационная история синтетическая. Генератор содержит 600 нарядов за несколько
месяцев, связанные справочники и ожидаемые закономерности. Метки генератора не
передаются производственному детектору. Любые схемы или иллюстрации для проверки
фотографий не являются фото реального ремонта и не подтверждают промышленное качество.
Непубличные данные предприятия требуют отдельного разрешения.

## Границы

- ИИ не выполняет техническую экспертизу безопасности оборудования и не заменяет
  мастера. Похожие фото и необычный расход — основания для проверки.
- Внешняя модель требует API-ключ, доступ к модели, бюджет и сеть; недоступность
  отображается явно. Минимизация текста не гарантирует удаления лиц/табличек с фото.
- Рейтинг не является оценкой профессиональной пригодности или основанием кадрового
  решения. Повторный ремонт не доказывает вину конкретного работника.
- Статистический сигнал не равен доказанной причине или валидированному прогнозу.
- Эффект пилота и промышленная точность ИИ пока не заявляются измеренными.
- Публичный адрес обслуживается локальным компьютером. Для постоянного внедрения
  требуется согласованное размещение, резервное копирование и обслуживание.
- Реальная Android PWA, фоновые push/звук и мобильная сеть требуют физического замера.
- ERP, голос, QR, казахский язык и прогноз отказов не выдаются за реализованные,
  если отсутствуют в фактическом релизе. Они не заменяют обязательные функции.

Модель для явного Docker-подключения по умолчанию — `gpt-5.4`; можно переопределить.
Возможности ввода изображений и структурированного ответа сверены с
[официальной страницей модели](https://developers.openai.com/api/docs/models/gpt-5.4).
Наличие модели в документации не доказывает доступ конкретного API-проекта: это
проверяется отдельным живым запуском. Источник и ограничения видны в отчёте релиза.
