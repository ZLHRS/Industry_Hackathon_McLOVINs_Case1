# ТехНаряд — готовность после доработок, 8 октября 2026

Это повторная оценка по обоим предоставленным PDF. Исходный аудит 59/100 и 55/100
сохранён [отдельно](../hackathon-strict-audit-2026-10-08.md) как снимок до исправлений.
Ниже перечислены фактические результаты и оставшиеся границы, а не обещание балла жюри.

## Что изменено

1. **Полные справочники:** семь разделов с отдельными адресами, поиском, формами
   создания/редактирования и возвратом назад. Участки, оборудование и сотрудники
   архивируются. Бригады, материалы, шифры и нормы можно удалять, когда они не
   используются; связанные записи и смысл прошлых отчётов защищены.
2. **Результат для исполнителя:** оценка мастера, допустимая информация о проверке,
   рекомендации, активное время, паузы, норматив и отклонение. Сохраняются попытки;
   закрытая работа больше не отображается как ожидающая решения. В аудите видны имена.
3. **Выдача наряда:** выбор оборудования обязателен; кандидат выбирается среди людей
   выбранного участка на смене. Видны специальность, разряд, загрузка и очередь.
4. **Более строгая проверка ИИ:** близкие изображения отмечаются как повод для
   проверки; расход сравнивается с медианой сопоставимых закрытых ремонтов. Берутся
   только реальные несинтетические записи до сдачи, за 365 дней, максимум 50,
   минимум 5. Медиана не называется утверждённой нормой.
5. **Надёжность:** защищены гонки удаления справочников и сдачи работы, уточнены
   ошибки сохранения. Подтверждается готовность WebSocket и настоящего service worker
   в браузерных замерах. Производственные данные не сбрасывались.
6. **Материалы защиты:** 10 слайдов PDF/HTML, видео 1:27, текст выступления, Q&A,
   раскрытие компонентов и ИИ, план пилота, бланк физических испытаний.

## Публичная конфигурация

Адрес: https://technaryad.online. PostgreSQL, API и туннель подтвердили health;
web и worker работают. Ключ хранится в Docker secret; модель — `gpt-5.4`, vision
включён у worker, который обрабатывает фотографии. API не выполняет vision-задания.
Защищённый WebSocket подключился у мастера, исполнителя и руководителя.

Новые сдачи используют новую конфигурацию. Сохранённые прежние fallback-отчёты
и исторические синтетические проверки не переписываются. Демонстрационная запись
намеренно показывает режим без внешней модели; она подписана соответствующим образом.
Домашний компьютер, Docker и туннель должны оставаться включёнными.

## Что ещё нужно подтвердить

- На физических Android: установка PWA, push со звуком в фоне, фото по мобильной
  сети ≤10 с, статус на другом устройстве ≤5 с, выдача ≤60 с/≤6 касаний, офлайн и
  возврат связи. Для этого подготовлен [протокол](device-acceptance.md).
- На разрешённых реальных фото: разметка мастерами до просмотра ответа модели,
  отдельные ремонты в проверочной выборке, доли ложной приёмки и лишнего возврата.
- На пилоте: исходное время выдачи, реакция на срочный наряд, полнота отчёта,
  повторные ремонты и полная стоимость эксплуатации. Пример «600 × 1 мин = 10 ч»
  в презентации — иллюстрация, не измеренный эффект предприятия.
- Для постоянной эксплуатации: размещение, полный аварийный перенос вместе с
  фотографиями/секретами, политика доступа и согласованные правила обработки фото.
- Команде: репетиция 3+3 минуты и самостоятельное объяснение графа состояний,
  конкурентных изменений, ИИ-ограничений, формул аналитики и выбора компонентов.

Нельзя честно заменить эти доказательства заявлением «100 из 100».
