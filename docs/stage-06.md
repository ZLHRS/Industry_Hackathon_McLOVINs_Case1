# Этап 6 — проверка ремонта и решение мастера

## Как пользоваться

1. Мастер выдаёт наряд и при необходимости добавляет фото «до».
2. Исполнитель принимает наряд, начинает работу, прикладывает фото «после»,
   указывает неисправность, конкретные выполненные действия и расход материалов.
   Если материалы не использовались, он объясняет почему.
3. После сдачи worker проверяет эту версию отчёта. Карточка обновляется через WebSocket.
4. В карточке видны вывод, замечания, оценка при наличии оснований, материалы,
   фотографии и сравнение времени с нормативом. История предыдущих проверок сохраняется.
5. Мастер принимает ремонт, возвращает его на доработку либо принимает с обоснованием,
   если проверка требует решения человека. Оценку можно изменить с указанием причины.
   Исходная оценка ИИ остаётся в истории.

## Настройка реальной модели

Приложение использует OpenAI Responses API, строгое JSON-описание ответа и закреплённую
модель gpt-4.1-mini-2025-04-14. Имя модели можно изменить в настройках при совместимости
с изображениями и Structured Outputs. Реальная доступность зависит от API-проекта.

В приватный .env добавьте:

~~~dotenv
NARYADAI_AI_API_KEY=your-private-api-key
NARYADAI_AI_MODEL=gpt-4.1-mini-2025-04-14
NARYADAI_AI_VISION_ENABLED=false
~~~

Ключ не отправляют в чат, Git или frontend. После изменения .env перезапустите worker.
Проверка подключения из терминала Ubuntu:

~~~bash
uv run --locked python scripts/check_ai.py
~~~

Команда делает один внешний запрос с синтетическим техническим текстом без БД и фото.
Успешный ответ подтверждает подключение, но не измеряет качество проверки ремонта.
Затем создайте и сдайте новый наряд: уже сохранённый fallback не переписывается автоматически.
Без ключа сохраняется отчёт локальных проверок с явной передачей решения мастеру.
Он не выдаётся за ответ внешней модели. Стандартные тесты не обращаются к платному API.

Для фотографий оборудования, разрешённых к внешней обработке, включите
NARYADAI_AI_VISION_ENABLED=true. При загрузке приложение удаляет EXIF и геометки.
Оно **не размывает автоматически лица, бейджи и видимые надписи**: для демонстрации
нужны фотографии оборудования без персональных или конфиденциальных данных.
Отключённый vision явно отражается в ограничениях отчёта.

Отправляется ограниченный набор технических данных. Имена и логины известных сотрудников,
инвентарные идентификаторы и распространённые контактные данные маскируются.
Это минимизация данных, а не гарантия распознавания любых персональных сведений
в произвольном тексте. Полные карточки, журнал событий, токены и пароли не передаются.
Параметр store:false отключает хранение объекта Responses для последующего получения;
он не является обещанием полного отсутствия хранения у провайдера.

## Надёжность и границы доказательств

- Сдача и постановка проверки в очередь — одна транзакция. Повтор запроса не создаёт
  новую проверку. Старые синтетические наряды не отправляются провайдеру автоматически.
- Отдельные циклы worker обрабатывают outbox, сроки, push и ИИ: медленная модель
  или полный обход сроков не задерживают следующую итерацию отправки обновлений.
- Worker берёт задание с ограниченной по времени блокировкой и выполняет сетевой запрос
  вне транзакции. Повторы ограничены; после недоступности провайдера решение остаётся мастеру.
- Поздний ответ не применяется к отменённому наряду, другой сдаче или новой попытке ремонта.
  Комментарий мастера сам по себе не должен терять результат проверки текущей сдачи.
- Дубликат определяется по точному хешу нормализованного изображения. Это не поиск
  всех похожих изображений: кадрирование и существенное изменение могут обойти проверку.
- Время съёмки, переданное клиентом, не считается независимым доказательством свежести.
  Дата загрузки показывает поступление файла в систему. Отсутствие достоверной даты отмечается.
  В текущем приложении даже согласованные клиентские даты оставляют результат на проверке
  мастера. Три рекомендации модели и предварительный балл видны в объяснении, но не
  превращаются в подтверждённую приёмку. Автоматического закрытия ремонта нет.
- Время работы, пауз и общее время попытки считаются по событиям отдельно. Пауза наряда
  или длительность ремонта сами по себе не доказывают фактический простой оборудования.
- Уверенность — самооценка модели, а не измеренная вероятность исправности оборудования.
  Фотографии не подтверждают скрытые дефекты, испытания под нагрузкой и безопасный допуск.
- Текст и надписи на фото — недоверенные данные. Модель не получает инструменты изменения
  наряда; окончательное закрытие выполняет авторизованный мастер.

## Проверки

Локально выполнено 6 октября 2026:

- 284 backend-теста на Python 3.13.13, включая настоящую PostgreSQL; покрытие с учётом
  ветвлений 90,97%. Проверены конкуренция worker, повтор сдачи, восстановление lease,
  ограниченные повторы, поздний ответ, права мастера и сохранение исходной оценки.
- 25 из этих тестов проверяют транспорт провайдера: структурированный ответ, отказ,
  429/5xx, таймаут, ограничения объёма, маскирование данных и изображения до/после.
  Это тестовые ответы, не измерение качества внешней модели.
- Ruff, форматирование, строгий mypy, frontend lint/types/format, 26 Vitest-тестов,
  production PWA и Python wheel/sdist — проходят.
- 9 сценариев в настоящем Edge через HTTP/PostgreSQL — проходят; приёмка с обоснованием
  и оценкой, возврат на доработку, новая попытка, офлайн-повтор, приватный кэш и роли.
  Два клиента: появление наряда 2412 мс, изменение открытой карточки 1589 мс
  в итоговом прогоне. Порог оставлен 5 секунд.
- Русский отчёт визуально просмотрен при ширине 390 и 1440 px. Это эмуляция размеров
  окна в настольном браузере, не проверка физического телефона.
- Миграция 0004 применена к основной демобазе; Alembic не обнаружил расхождений.
  Сохранены 600 нарядов, 4059 событий, 1200 списаний и 570 исторических оценок.
  API и worker перезапущены; вход, карточка, уведомления и WebSocket проверены на 5173.
- Изолированные данные и процессы E2E очищены. Git staging/commit/push не выполнялись.

Независимое ревью: блокирующих дефектов кода не найдено; итог **PARTIAL** из-за
отсутствия проверки настоящего провайдера и качества на репрезентативных фото.

Живой API и качество на реальных фотографиях **не проверены**: настоящий ключ не настроен.
Контрольный набор настоящих ремонтов с экспертными оценками, физические Android/iOS,
HTTPS-развёртывание и внешняя push-доставка остаются открытыми проверками.
