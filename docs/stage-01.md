# Этап 1: фундамент НарядAI

Дата проверки: 5 октября 2026. Этап завершает только фундамент, не весь MVP.

## Что сделано

- Прочитаны два PDF пользователя; схема жизненного цикла просмотрена как изображение.
- Матрица из 42 требований, две шкалы оценки, расхождения документов, план восьми этапов.
- Python 3.13.13, проектная .venv через uv 0.11.19, воспроизводимый uv.lock.
- Фабрика FastAPI, liveness, проверяемые настройки, Host/CORS, скрытые production docs.
- JSON-журнал без URL-параметров/тела запроса; server-generated request ID, безопасный ответ 500.
- Чистый домен: десять статусов кейса + отмена, роли действий, причины и UTC-время.
- Просрочка вычисляется; завершение исполнения и окончательное закрытие разделены.
- Три вердикта ИИ; отдельный флаг необходимости проверки мастером.
- Мастер может как принять отрицательно оценённую работу, так и вернуть положительно
  оценённую на доработку; причина обязательна, исходный вердикт сохраняется.
- Повторное исполнение очищает действующую оценку, предыдущая остаётся в событии перехода.
- Автотесты, проверки типов/стиля и подготовленный workflow GitHub Actions.

Для HTTP-проверки использовался временный runner в ignored tmp: он поднимал свой процесс,
проверял ответы и останавливал сервер. Проверку можно повторить командами запуска из README,
затем во втором терминале выполнить:

```bash
curl --fail http://127.0.0.1:8000/api/v1/health/live
curl --fail http://127.0.0.1:8000/openapi.json
```

Независимое ревью выявило отсутствие возврата на доработку по решению мастера вопреки
положительному ИИ-вердикту. Добавлены REQUEST_REWORK и регрессионные тесты.
Ранее при интеграционной сверке исправлены принятие из очереди, пересмотр после REWORK
и сохранение старого вердикта как действующего при повторной сдаче.

## Что ещё не проверено и не реализовано

- PostgreSQL/миграции, аутентификация, объектные права и постоянный аудит — этапы 2–3.
- PWA/телефоны, фото, push, real-time, ИИ-провайдер и аналитика — этапы 3–8.
- Тайминги ≤5 секунд/≤10 секунд/выдача за минуту пока не измерялись.
- GitHub Actions описан, но удалённый запуск не выполнялся.
- Docker не подключён к WSL; psql 16.15 есть, сервер на стандартном порту не отвечает.
- Liveness не означает готовность будущих БД, push или ИИ.
- Высокое покрытие существующего кода не означает покрытие всех требований кейса.

Объектные права и запись событий в БД нельзя подменять имеющимся доменным guard ролей.
Персональные/производственные данные в репозиторий не добавлялись.
