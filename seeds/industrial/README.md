# Локальная история ремонта

Отдельный воспроизводимый **синтетический** набор для просмотра приложения и защиты проекта.
Имена сотрудников вымышлены; оборудование, работы и интервалы подобраны правдоподобно,
но не являются выгрузкой предприятия. В названиях и описаниях нет префикса «ДЕМО».
Происхождение сохраняется в `is_synthetic` и служебных метаданных, а не повторяется в каждой карточке.
Настоящие фотографии и результаты внешней ИИ-модели не подделываются.

Весь генератор, команды и его тесты находятся в этой папке. Приложение её не импортирует.
Удаление `seeds/industrial/` с диска не ломает API и не удаляет уже записанные данные.
Для удаления данных сначала выполните команду `clear`, затем при желании удалите папку.

## Подготовка и заполнение

macOS/Linux/WSL, команды из корня репозитория. PostgreSQL и миграции должны быть готовы.
Перед заменой или очисткой остановите API и worker; после операции запустите их снова.
Frontend останавливать не требуется. Старые сессии после замены больше не действуют.

```bash
uv run --locked python -m seeds.industrial status
# Только для пустой базы:
uv run --locked python -m seeds.industrial apply
# Явная замена текущего локального набора с обязательной резервной копией:
uv run --locked python -m seeds.industrial replace --confirm REPLACE-LOCAL-DATA
```

По умолчанию история привязана к моменту запуска, seed равен `2026`.
Чтобы воспроизвести тот же набор, укажите время и seed явно:

```bash
uv run --locked python -m seeds.industrial apply --anchor 2026-10-06T12:00:00+05:00 --seed 2026
```

Повтор `apply` с той же датой и seed не создаёт дубликатов и не меняет пароль.
Иные параметры в непустой базе требуют явной команды `replace`.
Для обновления текущих заданий относительно нового дня также используйте `replace`.
Ни API, ни worker не запускают сид автоматически.

## Вход

- Мастер: `master.sadykov` или `master.orlova`.
- Исполнитель: `exec.amanov`; полный список — в файле учётных данных.
- Руководитель: `manager.tulegen`.
- Администратор: `admin.karim`.

Случайный общий локальный пароль и полный список логинов записываются в
`var/industrial-credentials.txt` (права 600, Git игнорирует файл). Пароль не выводится
в консоль. Для заданного пароля перед запуском установите `NARYADAI_SEED_SECRET`
через скрытый ввод, а после запуска удалите переменную. Общий пароль предназначен
только для этого локального набора; не переносите его в рабочую эксплуатацию.

Пароль входа в приложение и пароль подключения к PostgreSQL — разные значения.
Для приложения используйте строку `Password:` из файла выше. Подключение к БД
задаётся `NARYADAI_DATABASE_URL` в окружении или `.env`; окружение имеет приоритет.
`scripts/dev_database.py start` проверяет соответствие этой конфигурации локальному
кластеру и проверяет вход перед сообщением о готовности. При расхождении исправьте
конфигурацию, используя приватный `var/postgres/app-password`; пересоздавать базу
или применять `replace` для исправления пароля не требуется.

Набор создаёт 4 участка, 3 бригады, 25 единиц оборудования, 19 сотрудников,
20 шифров неисправностей, 40 материалов, 51 совместимый норматив и 600 нарядов.
Из них 588 закрытых и 12 текущих; есть просрочки, доработки, 66 записей простоя
и 10 рассмотренных отказов. Исторические оценки — решения мастеров без вызова модели.

Откройте `http://localhost:5173`, войдите заново, откройте «Наряды» или «Отчёт».
Для полной истории выберите последние четыре месяца, для текущих заданий — текущую дату.
Исторические решения мастера доступны без платных ИИ-вызовов. Сид не создаёт заданий
на отправку фотографий внешней модели.

## Очистка и резервные копии

```bash
uv run --locked python -m seeds.industrial clear --confirm CLEAR-INDUSTRIAL
```

Команда очищает только базу с маркером этого набора и сохраняет структуру таблиц,
миграции, `.env` и API-ключ. После очистки можно загрузить набор снова или заполнить
пустую базу своими данными. Если после сида появились новые наряды или справочники,
`clear` откажется их стирать. Изменения существующих записей сида, сессии, уведомления
и история взаимодействия удаляются вместе с набором; перед этим сохраняется копия.
`replace` — отдельная явно разрушительная команда для намеренной замены всего локального
набора, в том числе добавленных вручную записей.

Перед каждой непустой заменой/очисткой создаётся проверенный `pg_dump` в
`var/seed-backups/<время-id>/database.dump`, рядом — контрольная сумма и счётчики.
Папка закрыта правами 700, архив — 600; они не попадают в Git. При отсутствии
`pg_dump`/`pg_restore` или ошибке архива данные не меняются. Копия предназначена
для восстановления через PostgreSQL `pg_restore`, а не для публикации.
Исходные приватные фотофайлы не удаляются: архив хранит ссылки на них.

Запись блокируется на время копирования; очистка и заполнение выполняются одной
транзакцией. Ошибка заполнения откатывает удаление. Команды запрещены в production,
на удалённых адресах и для неподдерживаемых схем подключения. SQL не использует CASCADE.

## Проверки

```bash
uv run --locked python -m pytest seeds/industrial/tests -q
uv run --locked ruff check seeds
```

Интеграционные тесты создают отдельную временную схему в базе `*_test` и не меняют
основную базу. Проверяют повторный запуск, отказ очистки чужих данных, откат ошибки,
резервное копирование и действительное восстановление архива. Тесты генератора
проверяют связи, порядок событий, времена и происхождение данных.

Проверено при внедрении 06.10.2026: **28 тестов набора**, включая PostgreSQL,
восстановление архива, учётные данные и настоящий отчёт; дополнительно два теста
Excel-карточки. Проверены 24 сочетания seed и времени запуска без будущих событий
и двойных активных назначений. Ruff, проверка типов команд обслуживания,
frontend lint/format/build проходят. В работающем приложении проверены новый вход,
аналитика, две Excel-выгрузки и браузер на desktop/mobile. Платных ИИ-вызовов при
заполнении и проверке набора не было.
